  ✓ 解決 OSM trail way 資料不足的問題

  ✓ 愈多人走過 = GPS 軌跡密度高 = 受歡迎度高

🎯 三種使用策略
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  策略 1: OSM 為主，GPS 輔助 (原有方式)
  適用: OSM 資料完整的區域
  ┌────────────────────────────────────────────────────────────────────────┐
  │ graph = graph_service.get_or_build_graph("area", bbox)                │
  │ graph_service.enrich_with_gps_traces(graph, "area", blend_factor=0.7) │
  └────────────────────────────────────────────────────────────────────────┘

  策略 2: GPS 為主 (新功能) 🆕
  適用: OSM 資料不足的區域
  ┌────────────────────────────────────────────────────────────────────────┐
  │ graph = graph_service.build_graph_from_gps_traces("area")             │
  └────────────────────────────────────────────────────────────────────────┘

  策略 3: 合併兩者 (推薦) 🆕
  適用: 想要最完整資料
  ┌────────────────────────────────────────────────────────────────────────┐
  │ osm_graph = graph_service.get_or_build_graph("area", bbox)            │
  │ gps_graph = graph_service.build_graph_from_gps_traces("area")         │
  │ graph = graph_service.merge_graphs(osm_graph, gps_graph)              │
  └────────────────────────────────────────────────────────────────────────┘

🔧 完整範例：靈活起終點的路線規劃
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌────────────────────────────────────────────────────────────────────────┐
  │ from app.services.graph_service import GraphService                    │
  │ from app.services.routing_service import RoutingService                │
  │                                                                         │
  │ # 初始化                                                                │
  │ graph_service = GraphService()                                         │
  │ routing_service = RoutingService(graph_service)                        │
  │                                                                         │
  │ # 建立圖資（選擇策略 1, 2 或 3）                                         │
  │ graph = graph_service.build_graph_from_gps_traces("yushan")            │
  │                                                                         │
  │ # 使用者的 GPS 位置（不在節點上也沒關係！）                              │
  │ user_lat, user_lon = 23.4750, 120.8650                                 │
  │ dest_lat, dest_lon = 23.4800, 120.8700                                 │
  │                                                                         │
  │ # 自動找到或建立節點（會切割路徑）🆕                                     │
  │ start_node = graph_service.find_or_create_node_at_point(               │
  │     graph, user_lat, user_lon, split_edges=True                        │
  │ )                                                                       │
  │ end_node = graph_service.find_or_create_node_at_point(                 │
  │     graph, dest_lat, dest_lon, split_edges=True                        │
  │ )                                                                       │
  │                                                                         │
  │ # 規劃路線                                                              │
  │ if start_node and end_node:                                            │
  │     route = routing_service.plan_route(                                │
  │         graph, start_node, end_node,                                   │
  │         preferences={'popularity': 0.7}                                │
  │     )                                                                   │
  └────────────────────────────────────────────────────────────────────────┘

⚙️ 重要參數
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  參數名稱                   預設值     說明
  ──────────────────────────────────────────────────────────────────
  blend_factor             0.7        GPS 權重 (0=純OSM, 1=純GPS)
  simplify_tolerance       0.0001     簡化容忍度 ≈ 11 公尺
  intersection_threshold   50.0       交叉點閾值 (公尺)
  max_distance             100.0      最大搜尋距離 (公尺)
  split_edges              True       是否允許切割邊
  buffer_distance          30.0       匹配緩衝距離 (公尺)

💡 最佳實踐
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  GPS Traces 品質:
    ✓ 至少 10-20 條軌跡才有統計意義
    ✓ 來自不同時間/人的軌跡更好
    ✓ 軌跡應有一定重疊（識別主要路徑）
    ✗ 避免 GPS 訊號差的軌跡

  參數調整:
    • simplify_tolerance: 越小越精確，但節點越多
    • intersection_threshold: 太小漏交叉點，太大假交叉點
    • blend_factor: 0.7 推薦（70% GPS + 30% OSM）
    • max_distance: 超過此距離不建立/切割節點

  策略選擇:
    • OSM 資料完整 → enrich_with_gps_traces()
    • OSM 資料不足 → build_graph_from_gps_traces()
    • 想要最完整   → merge_graphs()

❓ 常見問題
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Q: Trail way 資料太少怎麼辦？
  A: 使用 build_graph_from_gps_traces() 直接從 GPS traces 建立。

  Q: 起終點不在節點上？
  A: 用 find_or_create_node_at_point(split_edges=True) 自動切割。

  Q: 需要多少 GPS traces？
  A: 至少 10-20 條，越多越好。重要的是要有重疊。

  Q: 可以混用 OSM 和 GPS 嗎？
  A: 可以！用 merge_graphs() 或 enrich_with_gps_traces()。

  Q: 切割邊會改變原始資料嗎？
  A: 不會。只在記憶體中操作，不會存回快取。

  Q: 效能如何？
  A: 建圖需要時間但會快取，切割很快（< 0.01 秒）。
